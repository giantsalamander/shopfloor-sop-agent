# 演示视频脚本（B站，约 3-4 分钟）

## 录屏准备（录制前 10 分钟做完）
1. 终端A（Spark）：cd ~/shopfloor-sop-agent && source ~/envs/sop/bin/activate && python app.py
2. 终端B（笔记本）：ssh -L 7860:localhost:7860 -p 6002 asus_gx10@61.172.235.130 -N
3. 浏览器开 http://localhost:7860，先点一次"快速合规判定"做 warmup（首次推理慢，正式录制时秒回）
4. 确认状态栏：Nemotron up:nemotron / vision_cache: 4 files
5. OBS 录浏览器窗口 + 终端A（双画面或切换）

## 分镜脚本

### 0:00-0:25 开场（口播+字幕）
口播："这是 ShopFloor SOP Agent——跑在一台 NVIDIA DGX Spark 上的工厂 SOP 合规检查智能体。两个本地大模型：NVIDIA Nemotron 30B 负责标准理解和合规判定，阶跃星辰 Step3-VL 负责仪器面板和现场照片识别。所有数据不出这台机器。"
画面：DGX Spark 实物 → Gradio 首页 → 架构图（README 第2节）

### 0:25-0:50 输入
口播："工人上传两份东西：一份标准 SOP 文本，一份回传记录 CSV——4 个步骤的读数、用的仪器编号、现场截图。"
画面：mock/sop_sample.txt 内容 + worker_batch.csv 表格 + 4 张仪器面板图
口播埋点："注意其中藏了三个坑：一台校准过期的示波器、一个超量程读数、一个把 mV 当 V 报的单位错误。"

### 0:50-1:10 一键判定
操作：点"快速合规判定"按钮。
口播："点击后，Nemotron 先把标准拆成步骤图，然后 10 个确定性工具逐一校验——查仪器资产库、算公差、交叉核对照片读数。模型负责理解，工具负责事实，每一步都写 checkpoint，随时可以从任意一步重跑。"
画面：进度 → 结果摘要出现

### 1:10-2:10 结果讲解（核心段）
逐行指 findings 表：
- "第一条 12.4V，合格，PASS。"
- "第二条 1250V——系统查资产库发现这台示波器 TSC-DSO-22 校准 2026-08-27 就过期了，instrument_validator 直接判 FAIL，根因写进报告。"
- "第三条更隐蔽：工人报了 12400，单位 mV。tolerance_calc 换算后发现偏差 103233%，超公差 5% 判 FAIL——这就是单位错误被抓住的瞬间。"
- "第四条扭矩 45Nm，PASS。"
展开审计 trace JSON："每一次工具调用、参数、结果、时间戳都在——审计员可以完整回放。"
画面：findings 表特写 → trace 特写

### 2:10-2:40 多模态证据链
口播："照片这一侧是 Step3-VL 提前解析好的：4 张面板图全部读出结构化 JSON——12.4V、1250V、12400mV、45Nm，单位量程一个不差。更关键的是超量程那张，Step3-VL 还认出了面板右上角的红色三角告警，photo_evidence_check 据此触发交叉校验异常。视觉不止读数，还能发现表单之外的现场异常。"
画面：vision_cache JSON 特写 + panel_overrange.png 红三角特写

### 2:40-3:10 可恢复回退
口播："如果工人补拍了新照片，不用全量重跑——从 EvidenceParse 这一步重跑就行。"
操作：下拉选 evidence_parse → 再点判定 → 新报告。
口播："每步 checkpoint，回退成本等于单步。"

### 3:10-3:40 平台收尾（口播+字幕）
口播："整套系统跑在 DGX Spark 的 128GB 统一内存上：Nemotron 用 NVFP4 量化加 fp8 KV cache，65536 上下文；两个模型内存互斥，我们做了两阶段调度——视觉离线预缓存，在线判定零切换。数据全程本地，这是工厂场景的底线。"
字幕关键数字：128GB 统一内存 / NVFP4 / 65536 ctx / 4/4 视觉抽取 / 12 条审计 trace / 判定 100% 可复现
