> 本脚本所有数字/结论均已按 **`shopfloor-sop-agent` 当前代码与数据** 校对（校对日期 2026-09-29）。
> 文末附「事实核对表」，列出每条关键数字的**出处**；改动代码或 mock 数据后请复跑该表。

## 录屏准备（录制前 10 分钟做完）

1. 终端A（Spark）：`cd ~/shopfloor-sop-agent && source ~/envs/sop/bin/activate && python app.py`
2. 终端B（笔记本）：`ssh -L 7860:localhost:7860 -p 6002 asus_gx10@61.172.235.130 -N`
3. 浏览器开 http://localhost:7860。
   左侧两个输入框是**文件路径**（默认已指向 `mock/sop_sample.txt` 与 `mock/worker_batch.csv`）——
   **演示不需要现场上传文件**，保持默认路径直接点按钮即可。先点一次"🚀 快速合规判定"做 warmup（首次推理慢，正式录制时秒回）。
4. 确认状态栏三行（注意第 2 行）：
   ```
   Nemotron(:8000): up:nemotron
   Step3-VL(:8001): down        ← 快速模式下显示 down 是正常的
   vision_cache: 4 files
   ```
   Step3-VL 显示 `down` 不是故障：两个模型显存互斥，快速模式的视觉结果来自
   `checkpoints/vision_cache/` 的预解析 JSON（见 `app.py` 的 `status()`）。
5. OBS 录浏览器窗口 + 终端A（双画面或切换）。

## 数据流（录制前先对齐口径，否则容易讲错）

```
标准 PDF ──[① 系统侧/标准方，非本次演示环节]──> 标准条款文本 mock/sop_sample.txt
                                                  ├─ std_doc_parse：抽条款 / 阈值 / 设备要求
                                                  └─ sop_planner（Nemotron）→ 步骤图 + setpoint / ±tol
工人 ──[② 真正由工人回传的东西]──> worker_batch.csv（4 行读数 + 仪器SN + 照片路径）+ 4 张面板照片

两条线在 validate 回合：查资产库 → 算公差 → 交叉核对照片 → findings → compliance_judge → 报告
```

**关键口径**：工人侧只回传**读数 CSV 和照片**；标准 SOP 是**系统侧/标准方的产物**，不由工人回传。

**必须知道的实情**：当前 `shopfloor-sop-agent` 仓库里**没有任何 PDF 解析代码**
（`grep -rn 'pdf' --include=*.py` 只命中 `app.py:51` 那句 UI 说明文案"标准PDF→SOP→工人回传"）。
`step_ingest` 实际做的事就是 `Path(sop_path).read_text()`——读一份**已经落盘的纯文本**。所以：

- 录制这个 App 时**不要**说"现场把标准 PDF 解析成 SOP"，会被行家一眼看穿；
- "标准 PDF → SOP"属于**另一条管线**（`generic_pipeline.py`，即 usb4 / usb3.2 CTS 那套），
  想讲完整故事就在开场把它作为"前置环节"一笔带过，或单独拍一段"导入"镜头接上来。

### 0:25-0:50 输入（两条线，别混为一谈）
口播："这个 App 有两份输入，**它们的来路完全不同**。左边这份是**标准侧的条款文本**——标准 PDF 先被整理成条款，系统再用 Nemotron 把它拆成可执行步骤和公差，**它不是工人回传的**。右边这份才真正来自工人：一条回传 CSV，**4 行读数，跨 2 个步骤**——绝缘电阻测试 S1 测了 3 次，扭矩校验 S2 测了 1 次，每行都带仪器编号和现场照片。"
画面：`mock/sop_sample.txt` 内容 + `mock/worker_batch.csv` 表格 + 4 张仪器面板图
口播埋点："**别数错：是 2 个步骤 4 行读数，不是 4 个步骤。** 这 4 行里埋了**两处会被判 FAIL 的问题**：第 2 行用的示波器校准已经过期；第 3 行工人把 12400 毫伏当成伏特上报了。"
提示：若想展示"标准 PDF → SOP"这一步，需切到 `generic_pipeline.py` 那条管线单独录；在这个 App 界面里说"解析 PDF"是不成立的（本仓库无 PDF 代码，`step_ingest` 只读文本）。

### 0:50-1:10 一键判定
操作：点"🚀 快速合规判定"按钮。
口播："点击后，Nemotron 先把标准拆成步骤图，然后 10 个确定性工具逐一校验——查仪器资产库、算公差、交叉核对照片读数。模型负责理解，工具负责事实，每一步都写 checkpoint，随时可以从任意一步重跑。"
画面：进度 → 结果摘要出现

### 1:10-2:10 结果讲解（核心段）
逐行指 findings 表（4 行）：
- "第一条 12.4V，相对设定值 12V 偏差 +3.33%，在 ±5% 内，PASS。"
- "第二条 1250V——系统查资产库发现这台示波器 `TSC-DSO-22` 校准 **2026-08-27** 就过期了。`instrument_validator` 直接判 FAIL，根因写进报告。"
  补充讲解："这一行 1250V 相对 12V 本身也是巨幅超差，但 `step_validate` 是**优先级链**——仪器掉队比公差掉队更严重，所以报告只记'校准过期'这一个根因。"
- "第三条更隐蔽：工人报了 12400，**单位填的是 mV**。系统按工人上报的单位直接比对（判定基准确实变成了 `12mV`），12400 对 12，**偏差 103233.333%**，超 ±5% 判 FAIL——这就是单位错误被抓住的瞬间。"
- "第四条扭矩 45.0Nm，0% 偏差，PASS。"
展开审计 trace JSON："每一次工具调用、参数、结果、时间戳都在——审计员可以完整回放。UI 面板默认只显示前 8 条，完整的 12 条在 `reports/<批次号>.json` 里。"

### 2:10-2:40 多模态证据链

### 2:40-3:10 可恢复回退
口播："如果工人补拍了新照片，不用全量重跑——从 EvidenceParse 这一步重跑就行，每步 checkpoint，回退成本等于单步。"

**演示要改成命令行（重要更正）**：UI 上每次点按钮都会生成**新的批次号**（`app.py` 里 `bid = f"B{uuid.uuid4().hex[:6]}"`），而恢复是按批次号去 `checkpoints/<批次>/` 读前序步骤的，所以**仅在下拉框里选 `evidence_parse` 再点按钮，并不能恢复上一次的批次**。正确做法是沿用同一个批次号：

```python
# 终端A 或 python -c
import pipeline
ctx = pipeline.run("RETEST0929",                     # ← 沿用已有批次号
                   "mock/sop_sample.txt",
                   "mock/worker_batch.csv",
                   resume_from="evidence_parse",      # 也可 validate / compliance_judge
                   vision_cache_dir="checkpoints/vision_cache")
```
操作：先在浏览器里跑一次拿到批次号（如 `B9db05c`），再用上面的固定批次号演示"跳过前面 4 步、直接从 evidence_parse 续跑"，并对比两次都生成了完整的 9 个 checkpoint 文件。

### 3:10-3:40 平台收尾（口播+字幕）
口播："整套系统跑在 DGX Spark 的 128GB 统一内存上：Nemotron 是 NVFP4 量化权重、`--max-model-len 65536`；两个模型显存互斥，我们做了两阶段调度——视觉离线预缓存，在线判定零切换。数据全程本地，这是工厂场景的底线。"
字幕关键数字：128GB 统一内存 / NVFP4 权重 / 65536 ctx / 4 文件视觉缓存 / 12 条审计 trace / 判定可复现（同一批次 100% 一致）
