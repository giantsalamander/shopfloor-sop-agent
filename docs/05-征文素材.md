# 黑客松十日谈征文素材（CSDN/知乎）

> 全部数据来自实机实测（DGX Spark gx10-3c74，2026-09-25 至 09-29），可复现。

## 建议标题
《一台 128GB 的桌面小钢炮，怎么塞下两个大模型跑工厂合规闭环——DGX Spark 黑客松十日谈》

## 叙事线（按真实时间线）

### Day 1：机器到手，先泼冷水
- DGX Spark 到手：GB10 Grace-Blackwell，20 核 Arm，128GB 统一内存，CUDA 13。nvidia-smi 一看显存全是 N/A——统一内存架构，GPU 独立显存查询根本不存在，第一个认知刷新。
- 内存之谜：free 显示 117GB 已用，进程 RSS 加起来才 47GB。查 /proc/meminfo 排除了 hugepages（HugePages_Total=0）——剩下的缺口是 vLLM 的 KV cache 池和统一内存映射，RSS 统计不到。教训：统一内存机器上别用传统思路算内存账。

### Day 2：把 Claude Code 装上，发现模型不行
- claude.ai 安装脚本在国内直接返回 App unavailable in region——geo-block。绕道 GitHub Release 拿 arm64 原生二进制，直连 40KB/s 下到猴年马月，换 ghfast.top 镜像 10 秒下完 105MB。
- Claude Code 说 Anthropic Messages API，vLLM 说 OpenAI Chat Completions，中间要翻译层。试了三个：PyPI 上的 ccproxy 是个同名占位包（简介是 get free proxy，作者都对不上）；LiteLLM 的 /anthropic/v1/messages 是直通转发到 api.anthropic.com（又被 geo-block 403）；真正的翻译端点是老 beta 的 /v1/messages——这个是翻 LiteLLM 源码翻出来的。
- 链路通了，但 Nemotron 一开口就是 Here is a thinking process——推理模型思考链外露。让它建文件，它输出 function=Write 的伪 XML 文本而不是结构化 tool_use。结论：Nemotron 做不了 agentic 编码助手，但做文本推理很能打。这个"失败"直接决定了参赛作品的架构：模型管理解、Python 工具管事实。

### Day 3：vLLM 重启把我上了一课
- 想把 Nemotron 上下文从 32768 拉到 65536，重启 vLLM——起不来，报 FlashInfer backend is not available。可 flashinfer 明明装着（0.6.18），原服务就是用 FlashInfer 跑了 23 天的。
- 排查半天发现根因：原服务是登录 shell 起的，/etc/profile.d/nv_paths.sh 会把 /usr/local/cuda/bin 注进 PATH；我用非交互 ssh 起，PATH 里没有 cuda，FlashInfer 的运行时检查直接判死。一行 export 解决。教训：复现服务要用原始环境起，别信"命令一样就行"。
- 65536 用登录 shell 一次点亮。期间把服务搞挂两次，都靠自动回退脚本救回来——后来这个"失败自动回退"思路直接进了参赛作品的 checkpoint 设计。

### Day 4：第二个模型来了，内存不够分
- StepFun 的 Step3-VL-10B（ViT 感知编码器 + Qwen3-8B 解码器）要上场做多模态。问题来了：Nemotron 占了 0.9x128 约 109GB，Step3-VL bf16 要 19GB——塞不下。
- 最终架构：互斥切换 + 视觉预缓存。四个脚本 run/stop-nemotron、run/stop-step3vl，起一个自动停另一个；视觉解析离线批量做完存 JSON 缓存，在线判定只跑 Nemotron。演示零切换等待——约束逼出来的设计，反而成了作品亮点。

### Day 5：推理模型不肯好好说 JSON
- Step3-VL 读仪器面板，读数全对（1250V、45Nm、12400mV 一个不差），但输出是思考链散文，JSON 解析 0/4。
- 第一反应 guided_json（vLLM 结构化输出）——对 Step3-VL 无效，照样思考链。换 response_format type=json_object——token 级强制合法 JSON，4/4 全过。这是整个项目最重要的模型侧结论：推理模型的结构化输出，别信 prompt 约束，用 API 级强制。
- 红色三角告警图标也是 Step3-VL 自己认出来的——我们只让它抽字段，它顺带把面板异常写进了 warnings。多模态模型的能力经常超出你的 schema。

### Day 6：作品成型
- 10 步流水线 + 10 个 Agent Skill + Gradio UI。实测批次：4 条工人回传，校准过期仪器和单位错误各抓一个 FAIL，根因、条款引用、12 条审计 trace 全齐。
- SOP-Bench 对齐：toolspec 直接用它家 Bedrock 格式导出，评测协议现成。

## 金句备选
- "统一内存不是内存变大，是账本变了。"
- "模型负责理解，工具负责事实——合规场景里，可复现比聪明重要。"
- "推理模型教会我的事：它想的都对，就是不好好说话。json_object 一上，全都老实了。"
- "约束逼出来的架构才是好架构：装不下两个模型，就发明了视觉预缓存。"
